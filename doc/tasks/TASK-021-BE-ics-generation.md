# TASK-021 · BE · ICS Calendar Invite Generation

## Context

Generates an `.ics` (iCalendar) file attached to booking confirmation and reschedule emails. No external library needed — the RFC 5545 format is simple enough to build with a Java string builder. The file lets visitors add the appointment to their own calendar app.

Depends on: TASK-018 (booking entity), TASK-020 (email service — consumes the generated bytes).

### RFC 5545 template

```
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//Unified Calendar//EN
CALSCALE:GREGORIAN
METHOD:REQUEST
BEGIN:VEVENT
UID:{uid}@unified-calendar
DTSTAMP:{now in UTC, format: YYYYMMDDTHHmmssZ}
DTSTART:{start in UTC, format: YYYYMMDDTHHmmssZ}
DTEND:{end in UTC, format: YYYYMMDDTHHmmssZ}
SUMMARY:{summary}
DESCRIPTION:{description}
ORGANIZER:mailto:{organizerEmail}
STATUS:CONFIRMED
END:VEVENT
END:VCALENDAR
```

**Key formatting rules (RFC 5545 compliance)**:

- Lines must be folded at 75 octets: if a line exceeds 75 characters, insert `\r\n ` (CRLF + space) and continue.
- Line endings must be `\r\n` (CRLF), not just `\n`.
- Dates in UTC are formatted as `YYYYMMDDTHHmmssZ` (e.g. `20240315T140000Z`).
- Special characters in `DESCRIPTION` must be escaped: `\n` → `\\n`, `,` → `\\,`, `;` → `\\;`.

```java
private static final DateTimeFormatter ICS_FORMATTER =
    DateTimeFormatter.ofPattern("yyyyMMdd'T'HHmmss'Z'").withZone(ZoneOffset.UTC);
```

### Line folding helper

```java
private String fold(String line) {
    if (line.length() <= 75) return line + "\r\n";
    StringBuilder sb = new StringBuilder();
    sb.append(line, 0, 75).append("\r\n");
    int i = 75;
    while (i < line.length()) {
        int end = Math.min(i + 74, line.length());
        sb.append(' ').append(line, i, end).append("\r\n");
        i = end;
    }
    return sb.toString();
}
```

### Attachment in email

In `EmailService`, call `IcsService` and attach the result:

```java
byte[] icsBytes = icsService.generate(
    booking.cancelToken(),
    "Meeting with " + admin.name(),
    "Visitor: " + booking.visitorName() + "\nPhone: " + booking.visitorPhone(),
    booking.slotStart(),
    booking.slotEnd(),
    admin.email()
);
String icsBase64 = Base64.getEncoder().encodeToString(icsBytes);

new Attachment("invite.ics", icsBase64)
```

Set `Content-Type: text/calendar; charset=UTF-8` — Resend's API passes the content type through via the filename extension for most clients; add explicit content-type in the `Attachment` record if the Resend API supports it.

### Reschedule: updated ICS

For reschedule emails, generate a new ICS with the updated `DTSTART`/`DTEND`. Use the same UID (cancel_token) so calendar clients update the existing event rather than creating a duplicate.

## Acceptance Criteria

- `IcsService.generate(...)` returns a non-empty byte array.
- The `.ics` file parses correctly in Apple Calendar, Google Calendar (import test), and Outlook.
- The UID is stable: generating two ICS files for the same booking produces the same UID.
- DTSTART and DTEND are in correct UTC format (`20240315T140000Z`).
- Long descriptions are correctly line-folded at 75 characters.
- Line endings are CRLF (`\r\n`), not LF (`\n`) only.
- The ICS is attached to the visitor confirmation email as `invite.ics`.
- The reschedule ICS uses the same UID, so calendar apps update the event rather than duplicate it.
